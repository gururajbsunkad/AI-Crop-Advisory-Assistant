10. Database Schema (Production SQL for PostgreSQL)

Create production-ready PostgreSQL tables.

Use UUID primary keys.

Enable UUID generation using PostgreSQL-supported functionality.

Create the following tables.

users
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
farmer_profiles
CREATE TABLE farmer_profiles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL UNIQUE REFERENCES users(id) ON DELETE CASCADE,
    full_name TEXT NOT NULL,
    phone TEXT,
    village TEXT,
    district TEXT,
    state TEXT,
    country TEXT NOT NULL DEFAULT 'India',
    farming_type TEXT,
    farm_size_acres NUMERIC(10,2),
    preferred_language TEXT DEFAULT 'English',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
crop_advisories
CREATE TABLE crop_advisories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,

    crop_name TEXT NOT NULL,
    crop_variety TEXT,
    location TEXT NOT NULL,
    soil_type TEXT,
    soil_ph NUMERIC(4,2),

    growth_stage TEXT,
    sowing_date DATE,

    irrigation_method TEXT,
    irrigation_frequency TEXT,

    fertilizer_usage TEXT,
    symptoms TEXT,
    pest_observations TEXT,
    disease_observations TEXT,
    weather_conditions TEXT,

    main_concern TEXT NOT NULL,
    additional_notes TEXT,

    status TEXT NOT NULL DEFAULT 'PENDING'
        CHECK (status IN ('PENDING', 'PROCESSING', 'COMPLETED', 'FAILED')),

    risk_level TEXT
        CHECK (risk_level IN ('LOW', 'MODERATE', 'HIGH', 'CRITICAL')),

    confidence TEXT
        CHECK (confidence IN ('LOW', 'MEDIUM', 'HIGH')),

    advisory_result JSONB,
    ai_model TEXT,

    error_message TEXT,

    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

Create indexes:

CREATE INDEX idx_crop_advisories_user_id
ON crop_advisories(user_id);

CREATE INDEX idx_crop_advisories_created_at
ON crop_advisories(created_at DESC);

CREATE INDEX idx_crop_advisories_status
ON crop_advisories(status);

CREATE INDEX idx_crop_advisories_risk_level
ON crop_advisories(risk_level);

Create appropriate database constraints and migration scripts.

Do not rely exclusively on application-level validation.

11. Row Level Security (RLS) / Data Isolation Rules

The application must ensure strict user data isolation.

A user must only be able to access:

Their own profile
Their own advisories

A user must never be able to access another user's advisory by changing:

/advisory/:id

The backend must always enforce ownership.

For every advisory query:

WHERE id = $1 AND user_id = $2

Never retrieve an advisory using only its ID.

Similarly, profile queries must use authenticated user identity.

If PostgreSQL deployment supports RLS in the selected architecture, implement appropriate RLS policies.

If the backend uses a privileged database connection, application-level ownership checks remain mandatory.

14. AI System Prompt

Use the following conceptual system instruction for Gemini:

You are an AI-powered agricultural crop advisory assistant.

Your role is to analyze structured crop and field information and provide practical, cautious, farmer-friendly agricultural guidance.

You are not a replacement for a qualified agricultural extension officer, agronomist, plant pathologist, or local agricultural authority.

Use only the information provided by the user and generally established agricultural knowledge.

Do not invent:
- Soil test results
- Weather measurements
- Pest identification certainty
- Disease confirmation
- Crop yield
- Chemical dosage
- Local government recommendations
- Product availability
- Agricultural regulations

When information is insufficient, explicitly communicate uncertainty.

Never present a possible diagnosis as a confirmed diagnosis.

Separate:
1. Observed information
2. Possible explanations
3. Recommended actions
4. Preventive actions
5. Information that requires professional confirmation

Prioritize practical actions that reduce crop risk.

For chemical or pesticide-related recommendations:
- Avoid unsafe or highly specific instructions when critical information is missing.
- Recommend following the product label and local agricultural authority guidance.
- Include appropriate protective and environmental precautions.
- Do not encourage misuse or unsafe mixing of agricultural chemicals.

Do not promise crop recovery or increased yield.

Use clear, simple language suitable for farmers.

Return only the requested JSON structure.

All fields must follow the specified schema.
